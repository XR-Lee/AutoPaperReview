# Feature reference

This is the full list of what AutoPaperReview `0.1.10` provides. The [README](../README.md) has the short version and the `forecast-k1` run instructions. Behavior is described as shipped; the [Changelog](../CHANGELOG.md) records when each piece changed.

## What v0.1 provides

- Strict Pydantic models for artifacts, sources, evidence, issues, review packages, stages, and run manifests.
- A TOML-defined DAG with validation, resumable execution, content-hash caching, and atomic stage promotion.
- Built-in stages for source ingest, deterministic commands, prompt packets, legacy issue import, consensus, and Markdown/JSON reports. A report can emit one Markdown file with both `en` and `zh-Hans` (`bilingual = true` or `languages = ["en", "zh-Hans"]`). Missing translations are filled into `LocalizedText.translations` only for short fixture phrases; bilingual rendering does not silently fall back to the primary language, and incomplete pairing is refused before Markdown/PDF export.
- A deny-by-default network declaration gate. Commands never use a shell, and network-requiring stages must declare their scope.
- Python entry-point plugins under `autopaperreview.stages`.
- Migration support for the earlier bare issue-array and review-package JSON formats.
- Generated JSON Schema, a synthetic end-to-end example, unit tests, CI, and an open-source reference-stack snapshot.
- Optional SAR-shaped records: seven dimension scores on a 1–10 scale, narrative claims that require evidence IDs, related-work query sets, retrieved-source snapshots, and venue-specific conclusions for conferences and journals. No overall score is emitted by default. The chat adapter does not emit one. `rate` assigns the venue bin when it runs. Report Markdown (and PDF, if `reportlab` is installed) links each `[E2]` to the Evidence Index.
- Agent handoff: `execute_review` with `AgentJudgmentAdapter`, `visual_inspect` with `AgentFindingsInspector`, and agent-mode `related_work_search` record `awaiting_input` while their declared drop is missing, and the stages that do not depend on them still run. `status` prints the drop requests as JSON, `submit` checks a drop with the stage's own validation before writing it, and `run` exits 3 while a drop is awaited. `verify_excerpts = true` requires every quoted span in an agent judgment to resolve in the manuscript or a retrieved snapshot. `autopaperreview mcp` serves the loop to Claude Code, Codex CLI, or another MCP client over stdio, with paths confined to `--root` directories. See [Agent handoff and MCP](architecture.md#agent-handoff-and-mcp).
- A `literature_grounding` stage that emits multi-perspective queries and optional offline snapshots behind the network declaration gate.
- P0–P2 contract stages: `execute_review` (fixture JSON, deterministic checks, or an OpenAI-compatible chat adapter), snapshot excerpts, typed `Anchor`s, a report export gate, `ledger` / `agenda`, read-only `workspace_inspect`, `integrity`, and matched-setting `novelty`.
- Figure-grounded review: a visual route (`figure_grounded_v1`) plus prompt packets that require inspecting every numbered figure on the sibling PDF page. Caption paraphrase is not inspection.
- Listed contributions: the 3–4 author-numbered items are extracted, retrieved against, and audited one by one for evidence completeness. A single paper-level novelty paragraph is not sufficient.
- First-read review writing: issues can carry a `FirstReadNote` (what the paper said, a quote, why it matters). Prompt packets prepend a shared writing contract. Reports lead with a how-to-read note and inline quotes so a first-time reader can follow the argument without already knowing the paper.
- Declared ICLR rating (`rate`, coefficient set `apr-iclr-cap-v2`, the default): seven anchored bands (`sar_bands_v1`, scores 2/4/6/8/10), fatal-flaw caps, and a snap onto 1/3/5/6/8/10. The venue bin is the largest bin that does not exceed the capped raw score, so a raw 7 stays in 6. The gate is `min(claims, soundness) + 1`. Weights are unchanged from v1 (experimental soundness 0.30, claims 0.25, originality 0.15, importance 0.12, prior work 0.08, writing 0.05, community 0.05). Caps and exemptions are stored on the score. The weighted sum uses `math.fsum`, so a uniform band lands on the same bin on Python 3.10 through 3.13. This is not a fitted regression. `calibrate` orders several packages and requires `same_bin_justified` when two neighbors share a bin.
- Fusion rank (`rate` with `coefficient_set = "apr-fusion-v1"`): the locked candidate is `forecast-k1`. One holistic call simulates three reviewers (specialist, generalist, senior) on the full manuscript. Each gives a probability over the official ratings 1, 3, 5, 6, 8, and 10. The rank is the mean of the three expected ratings, clamped to 1.0–10.0. The same call's 1–6 decision sets the ICLR bin. `vote-k*`, `chair-k*`, `high-k*`, and `low-k*` are diagnostic. Older stored packages still rank by the candidate their samples support (`rebuttal-k2`, `matched-k2`, `panel-k2`, `expert-k2`, `audited-k1`, `mean-k3`, or an earlier placement, venue mean, or decision). See [Forecast rank](../README.md#forecast-rank-forecast-k1) and [public calibration eval](public-calibration.md).
- Public calibration eval (`calibrate-eval`): fetches public ICLR submissions, runs prompt packets plus a judgment adapter, and reports Spearman, Kendall tau-b, MAE, bin agreement, accept/reject AUC, a bin confusion table, and score spread. `scripts/select_public_calibration.py` draws a seeded 100-paper stratified sample into a gitignored cache. The generated run includes `related_work_search` before `rate`. Search mode defaults to `off`. `--related-work agent` reads a local findings drop, and `--related-work live` queries metadata providers. `--mode adapter` can select `OpenAICompatibleAdapter` with `--base-url` and `--model`. `--coefficient-set` defaults to `apr-iclr-cap-v2`. `apr-fusion-v1` turns on the holistic judgment and ranks by `forecast-k1` (`--holistic-mode forecast` and `--holistic-samples 1` are the defaults). The command does not fit weights, caps, bins, or the locked candidate. Manuscripts, forum ids, and the numeric report stay outside git. See [public calibration eval](public-calibration.md).
- Visual and format review (`pip install 'autopaperreview[visual]'`): `render_pages` writes hashed page PNGs, including an optional supplement as `S1`, `S2`, ... . `format_check` applies a pinned venue profile (`iclr2027` or `aaai2027`) to the main PDF and does not count supplement pages toward the page limit. `visual_inspect` accepts an adapter whose findings cite the page-image hash and a non-caption locator. `AgentFindingsInspector` reads a JSON drop after the pages were opened. `OpenAICompatibleVisionInspector` sends those page images to an OpenAI-compatible chat model. `HostedVisionInspector` can POST page images only when the network policy is `allow` and an API key is set; a missing key sends nothing. Findings move the rating only through fatal classes or clause ceilings. `init` mounts `visual_qa_v1` as route M9.
- Annotated manuscript PDF: a role-colored highlight, a margin tag such as `E7`, and an `APR reviewer` comment for every cited evidence id, plus an evidence-index page. `autopaperreview annotate` rebuilds that file from a finished run without calling the model. The report stage writes it when a sibling PDF and PyMuPDF are present. See [Annotated manuscript PDF](../README.md#annotated-manuscript-pdf).
- Related-work search before scoring: `related_work_search` derives the problem formulation and searches five keyword families (same problem, same technique, alternative formulations, standard baselines, adjacent tasks), plus name-only lookups for methods the manuscript itself names. Keyword queries are generic tokens. Live calls use arXiv, OpenAlex, and Semantic Scholar. HTTP 429 is retried and does not abort the rest of that provider. If every provider fails, times out, or none are available, `status=degraded` and the score does not drop. If at least one provider succeeds and another fails, `status=partial` names the failed providers and the report says the search may be incomplete. A failed provider never creates or strengthens a retrieval cap. Must-compare requires task overlap and technique or setting overlap, excludes surveys, reviews, datasets, benchmarks, and generators, and keeps at most three neighbours the judging agent confirmed. Live search writes a confirmation packet and stays `awaiting_confirmation` until a confirmation file or an explicitly configured confirmation adapter answers it. The judge's reason is kept verbatim. Cited bibliography entries are looked up by title, a batched arXiv id list, and DOI. Numeric markers and author-year cites count, wrapped reference lines stay with their entry, and the default bibliography budget is 60. OpenAlex title filters drop commas, colons, and quotes. HTTP 400 responses are cached with successful metadata. Semantic Scholar paces requests and can use `S2_API_KEY`; without a key, a remaining 429 skips that provider inside a short budget. Successful metadata is cached on disk under the project directory. Agent mode accepts a findings file and keeps a paper only when its id resolves in a provider payload. A confirmed pre-deadline paper that a successful provider returned, and that is absent from the baselines, can raise `missing_closest_neighbor` (cap 6) on a complete or partial search. A privileged or different-task baseline raises `unfair_baseline` (cap 5) on a complete or partial search, without a verified candidate, and always cites the manuscript baseline anchor. Concurrent work is discussion only. `mode = "pool"` compares against a local prior-work pool with no network call, drops records on or after `cutoff_date`, and logs a retrieved target paper on `target_leakage`. `prompt_packet` `input_mode = "proposal"` reviews a title and description and does not ask for a PDF. `novelty` and `rate` must depend on that search when it is in the same DAG. See [related-work search](related-work-search.md).
