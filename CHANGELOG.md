# Changelog

## Unreleased

- CVPR-tier `run` skips A1/A2 manuscripts with failing per-paper leak counts before prompting or invoking a model, records `skipped` / `leak_failed` with category counts, and reports skips separately in usage, rounds, and analysis. A0, prompts, thresholds, and scoring are unchanged; older A1/A2 caches need `prepare` again to populate per-paper counts.
- CVPR-tier command and replay answers recover the last schema-valid JSON fence or the last balanced top-level object after trying the full response, reject and log truncated/max_tokens outputs, and add JSON-only/no-tools/no-search instructions only to Grok prompts; scoring and token budgets are unchanged.
- CVPR-tier extraction treats blank layout lines as soft abstract breaks, stops at section headings, caps abstracts at 400 words, and recovers titles from compact preambles. A1/A2 recognize shared-column reference headings or dense dated citation runs while retaining body leak checks, and mask column-split titles, small caps, subtitles, and running headers without changing fail-closed thresholds.
- `calibrate-eval cvpr-tier` fixes abstract extraction, A1 acknowledgement removal, title masking, multi-batch probes, P-D passage generation, and decoys. A shared-line, cased, or inline abstract heading is accepted, with a layout extract tried before a raw extract. Papers that still have no abstract are counted in the probe output and the sample manifest, and the probe stops before any model call when that share is above 5%. A1 removes acknowledgement and funding sections through the references heading, and a residual heading counts as a leak. Title 4-grams are matched after line breaks, hyphenation, ligatures, and case are normalized, and a residual gram counts as a leak. Probe items are shuffled into batches of `--batch-size` (default 10); each batch is stored before the next one starts, and a later run resumes a completed batch. P-D builds a verbatim passage and three paraphrases from the manuscript when no passages file is given. Decoy titles are plausible recombinations or lexicon titles and are rejected when they match the catalog or `title_digests.json`.
- `calibrate-eval cvpr-tier` adds contamination probes, variant run directories, and stratified metrics. `probe` runs the P-A, P-T, and P-D templates in shuffled batches with synthetic decoys and optional arXiv controls. Scores are title token-F1, surname overlap, venue/year, DE-COP, and tier-QA. Probe files do not contain program tiers; the report joins them. `controls` fetches arXiv metadata at run time (the tests use a fixture feed). `decoys` writes synthetic stand-ins offline. Run directories are `runs/<model>/<variant>/<round>` when a variant or round is set, and the report pairs variants of one model. The primary metric is macro-AUC, with Cpop, oral-versus-rest (including the 2024 weighted form and a 2025 contrast), Horvitz–Thompson Spearman, Kendall, confusion, precision/recall, and labelled share, quadratic-weighted kappa, year-by-tier stratified bootstrap, paired bootstrap, DeLong, Holm, and Benjamini–Hochberg. `--repeats` stores repeat scores and the report gives ICC(2,1) and ICC(3,1). `rounds.jsonl` lists every candidate. An analysis CSV sits beside the markdown. Models run through the command backend only. The adapter backend is refused and no API key is read.
- A host agent can be the reviewer in a normal `run`. `execute_review` with `AgentJudgmentAdapter`, `visual_inspect` with `AgentFindingsInspector`, and `related_work_search` with `mode = "agent"` raise `AwaitingInput` when their declared drop is missing. The stage is recorded as `awaiting_input` (a new `StageStatus` value in `run-manifest.schema.json`) with the files to read and, for a review judgment, the packet digests to echo. Downstream stages are `pending` with `blocked_by`; independent stages still run. Before this change, `validate` refused an `AgentJudgmentAdapter` config until the drop existed, but the packets the drop must echo were written only by `run`. Handler versions are unchanged, and a run written by 0.1.10 is reused stage for stage.
- `run` exits 3 while a stage awaits a drop and prints JSON on failure (`failed_stage`, `error`) and when another run holds the project (`busy`). A run holds `<run>/.lock`; a second run of the same project raises `RunLockedError` and does not write the manifest.
- `autopaperreview status` prints the run state, awaiting drop requests, open related-work confirmations, input changes since the last run, report outputs, and the next step. `--detail` adds a fill-in drop template. `autopaperreview submit` checks a drop with the stage's own validation and writes it to its declared path only when the check passes.
- `execute_review` accepts `verify_excerpts = true`. `AgentJudgmentAdapter` then rejects a drop whose evidence excerpt, first-read quote, or issue anchor excerpt does not resolve in the manuscript or a retrieved snapshot. The parameter enters the stage signature only when true.
- `init --adapter agent` writes an `AgentJudgmentAdapter` review stage with `fixture_path = "judgment.json"` and `verify_excerpts = true`. `init` escapes the project id and title as TOML strings and checks the id pattern before writing. It prints one JSON document instead of two.
- `autopaperreview mcp` serves `init_project`, `validate`, `run`, `status`, `read_input`, `drop_template`, `submit_drop`, and `report` to an MCP client over stdio. It uses the standard library only. Paths are confined to `--root` directories, long text is paged, `run` sends per-stage progress notifications, and stdout carries protocol messages only.
- The CLI reports `OSError`, `RuntimeError`, and `ImportError` as one `error:` line with exit code 2 instead of a traceback.
- Model-call timeouts default to 7200 seconds. That covers `DEFAULT_MODEL_TIMEOUT_SECONDS`, `execute_review`, visual inspection, hosted vision, related-work confirmation, the CVPR tier chat and command backends, the `command` stage, and the ClaimNov pilot TOML. An explicit `timeout_seconds` in a config is still the value that is used. A later `run` still skips stages that already succeeded. Inside a failed `execute_review` or `visual_inspect`, a finished judgment whose stored request matches is replayed instead of calling the model again. `--force` calls the endpoint again. `calibrate-eval cvpr-tier run` skips a paper that already has a non-empty answer.
- Python 3.10 is supported (Ubuntu 22.04's system Python). `tomllib` falls back to the `tomli` backport, which is a dependency only below 3.11. CI adds 3.10. On 3.10 the test suite, the synthetic example (byte-identical `review_report.md`) and the committed schemas match 3.13. Rating sums already use `math.fsum`, so bins do not depend on the interpreter's `sum()`.
- `calibrate-eval cvpr-tier` isolates model handoffs. Replay packets use a 12-hex id outside the cache. The command backend passes the prompt on stdin, starts in an empty temporary directory, and scrubs credential variables. `prepare --variant A1` or `A2` anonymizes manuscripts and writes leak counts only. `benchmarks/cvpr_tier/sets.json` registers S24-P, S24-C1, S24-D2, and S24-C2. `cvpr-tier lock` writes hashes and protocol defaults. A sealed run needs `--confirm --lock`. `report --confirm` opens a sealed set once. Each run writes `usage.json`. Grok stays on the local CLI. No API key is added.
- `calibrate-eval cvpr-tier` reports whether an existing review mode's rank separates CVPR accepted tiers (oral, highlight, poster). The sample is stratified and seeded. Per-paper tiers stay in `heldout/tiers.json`. Each run records a free-form model id, such as `grok-4.7-cursor`, `opus-local`, or `astra-local`. `replay` is a pending/answers handoff for a Cursor agent. `command` runs that model's own local CLI from an argv template. The report compares models on the same sample and does not fit a cutoff. Venue profiles `cvpr2025` and `cvpr2026` pin the public dates and the 8-page format.
- `prompt_packet` accepts `input_mode = "proposal"` for a title and a short description. The packet does not ask for a PDF or a figure inspection. Handler version is 6. `manuscript` is unchanged.
- `related_work_search` accepts `mode = "pool"`. It reads a local prior-work JSON file and does not call a provider. `cutoff_date` drops records dated on or after that day. `blocked_ids` remove the target paper and record it on `target_leakage`. Handler version is 8.
- `benchmarks/claimnov_pilot` draws a seeded 200-id sample and aggregates published ClaimNov verdicts on those ids. The APR model call is not made when `APR_MODEL_API_KEY` is unset or the checkout has no proposal text or pool abstracts.

## 0.1.10 - 2026-10-25

- `apr-fusion-v1` ranks by the preregistered candidate `forecast-k1`. `holistic_mode` gains the locked value `forecast` (`LOCKED_HOLISTIC_MODE`) with K=1 (`LOCKED_HOLISTIC_SAMPLES`): one call per paper simulates the three reviewers of `anchors.FORECAST_SEATS` (the `specialist`, `generalist` and `senior` profiles, text unchanged) reading the full manuscript packet. For each reviewer the call writes a one-sentence `summary`, up to two `strengths` and `weaknesses`, the official `rating` that reviewer would most likely submit, six `probabilities` (that the reviewer's official rating is 1, 3, 5, 6, 8, 10, in that order, summing to one) and a `confidence` 1–5; then its own `predicted_mean` and the 1–6 decision on the round 5–10 scale text. Each distribution is normalised (a sum away from one is counted as `renormalized`; a dictionary keyed by rating is reordered) and turned into an expected rating `sum(p_i * r_i)` (`anchors.expected_rating`). The per-call sample is the mean of the three expected ratings (`anchors.forecast_mean`), the shipped rank is that sample clamped to 1.0–10.0, and the decision sets the bin. The mean of the three integer ratings is stored as `vote-k*` and is diagnostic, as are `chair-k*`, `high-k*` and `low-k*` (the per-call extremes of the expected ratings). An integer off the official list is counted as `off_scale` and an integer that is not the rating with the most mass as `mode_mismatch`; neither is retried. `--holistic-samples 2` runs two concurrent forecast calls and still ranks by the first. `holistic_mode = "rebuttal"` keeps the previous candidate `rebuttal-k2` (K simulated three-reviewer reviews of the full manuscript carried through the authors' response, ranked by the mean official rating held at the end of the discussion), and `"matched"`, `"panel"`, `"expert"`, `"audited"` and `"mean"` keep theirs, with their prompt text and packets unchanged; a package that stored only one of those families still ranks by `rebuttal-k2`, `matched-k2`, `panel-k2`, `expert-k2`, `audited-k1` or `mean-k3`. `our_score.json` records `forecast_samples`, `vote_samples`, a `forecast` summary of per-call seat ids and numbers without free text, and `main_text`. `calibrate-eval run` defaults to `--holistic-mode forecast --holistic-samples 1`.
- `apr-fusion-v1` ranks by the preregistered candidate `matched-k2`. `holistic_mode` gains the locked value `matched`: K matched-panel calls run together and do not see each other (the default K is 2). Each call sees the manuscript's main text only: the `## Source Text` section of the packet is cut at the first standalone reference-list heading found at or after `anchors.MAIN_TEXT_MIN_SHARE` of the text and capped at `anchors.MAIN_TEXT_MAX_CHARS` characters, with a marker line where the cut happened (`model_exec.main_text_packet`); the other packet sections are kept. The call simulates the four topic-matched reviewers of mixed seniority the venue would assign, in the declared seats of `anchors.MATCHED_SEATS` (insider, junior, neighbour, senior, each with a profile of what that reviewer weighs), is told they read the main text once and that a detail deferred to the appendix is not missing, and is given the venue's rating norms in words (acceptance rate, how often each official rating is given, what an accepted and a rejected paper's ratings usually look like, and that these are not a quota for one paper). For each reviewer it writes a one-sentence summary, up to two strengths and weaknesses, the official `rating` (1, 3, 5, 6, 8, 10; an integer off that list is kept and counted as `off_scale`) and a `confidence` 1–5; then a short `discussion`, its own `predicted_mean` on the round 5–8 scale text, and the 1–6 decision. The per-call panel mean is the mean of the four ratings and the rank is the mean of the first two panel means; the decision sets the bin. `chair-k*`, `high-k*` and `low-k*` are diagnostic. `holistic_mode = "panel"`, `"expert"`, `"audited"` and `"mean"` keep the previous candidates with their prompt text and full packet unchanged, and a package with only two mixed-role panels, two expert reads, an audited mean or three plain venue means still ranks by `panel-k2`, `expert-k2`, `audited-k1` or `mean-k3`. `our_score.json` records `matched_samples`, a `matched` summary of per-call seat ids and numbers without free text, and `main_text` (source characters, shown characters, cut kind).
- `apr-fusion-v1` ranks by the preregistered candidate `panel-k2`. `holistic_mode` gains the locked value `panel`: K panel calls run together and do not see each other (the default K is 2). Each call simulates the four reviewers the venue would assign, in the declared roles of `anchors.PANEL_ROLES` (specialist, generalist, methodologist, senior, each with a profile of what that reviewer weighs), and is told to predict typical reviewers rather than a better one. For each reviewer it writes a one-sentence summary, strengths, weaknesses, the official `rating` that reviewer would submit (the venue's choices 1, 3, 5, 6, 8, 10; an integer off that list is kept and counted as `off_scale`, not retried) and a `confidence` 1–5; then a short `discussion`, its own `predicted_mean` on the round 5–7 scale text, and the 1–6 decision. The per-call panel mean is the mean of the four ratings and the rank is the mean of the first two panel means; the decision sets the bin. `chair-k*` (the model's own mean after its panel), `high-k*` and `low-k*` (the per-call extremes) are diagnostic. Nothing is verified against the manuscript and no call is conditioned on another. `holistic_mode = "expert"`, `"audited"` and `"mean"` keep the previous candidates with their prompt text unchanged, and a package with only two expert reads, an audited mean or three plain venue means still ranks by `expert-k2`, `audited-k1` or `mean-k3`. `our_score.json` records `panel_samples`, `chair_samples`, `high_samples`, `low_samples`, and a `panel` summary of per-call role ids and numbers, without free text.
- `apr-fusion-v1` ranks by the preregistered candidate `expert-k2`. `holistic_mode` gains the locked value `expert`: K expert reads run together and do not see each other (the default K is 2). Each read addresses the model as a senior researcher in the paper's subfield and fills the JSON in a fixed order: the area and a `contribution_type` (`anchors.CONTRIBUTION_TYPES`: method, theory, analysis, benchmark, system, application, position, each with the standard reviewers hold it to), up to five recalled `prior_work` entries with whether the submission cites them and whether the model is sure they exist, a short `field_context` on the baselines and gains the area treats as meaningful, the review-form triad `soundness`, `presentation`, `contribution` on 1–4, strengths and weaknesses, and only then the venue-scale mean on 1.0–10.0 and the 1–6 decision. Nothing is verified against the manuscript and no call is conditioned on another. `holistic_mode = "audited"` and `"mean"` keep the previous candidates with their prompt text unchanged, and a package with only an audited mean or three plain venue means still ranks by `audited-k1` or `mean-k3`. `our_score.json` records `expert_samples`, `form_samples`, and an `expert` summary of per-read numbers and the type, without free text.

## 0.1.9 - 2026-10-21

- Added a public-repo confidentiality policy ([CONFIDENTIALITY.md](CONFIDENTIALITY.md), [AGENTS.md](AGENTS.md)) and a tracked-file check that rejects review work directories, document and image files outside an allowlist, submission-id patterns, and SHA-256 digests of blocked strings. (#11)
- Replaced contribution-list fixtures with synthetic sentences.
- Added `related_work_search`. Before novelty or prior-work scores, the stage derives the task, inputs, outputs, assumptions, and setting, then builds keyword queries for the same problem, the same technique, alternative formulations, standard baselines, and adjacent tasks. Manuscript text is not sent to a provider.
- Live retrieval uses the arXiv API, OpenAlex, and Semantic Scholar, and logs offline, timeout, or rate-limited providers without inventing papers. Agent mode reads a findings drop and keeps a candidate only when the provider payload resolves the same id and title.
- Candidates record venue, year, link, a one-line summary, whether the bibliography cites them (normalized title or arXiv/DOI id), and whether they are prior, concurrent, or undated relative to the venue submission deadline. Tiers are must-compare, should-discuss, and optional. Must-compare requires both task overlap and technique or setting overlap. Surveys, reviews, datasets, benchmarks, and generators stay should-discuss at most. Mentioning an input modality is not enough. At most three confirmed neighbours stay must-compare, ranked by relevance. The judging agent confirms each one with a one-line reason before a retrieval cap can cite it. Unconfirmed neighbours are discussion only.
- Experiment comparison flags missing must-compare baselines, privileged inputs such as ground-truth scale, and baselines that solve a different task. Clause advice follows `apr-iclr-cap-v1`. The search stage does not write an overall score.
- `FatalClass.missing_closest_neighbor` caps `apr-iclr-cap-v1` at 6 (`prior_work_contextualization` ceiling 2, `originality` ceiling 4). The existing `unfair_baseline` signal is a blocking issue and keeps its cap of 5. `rate` applies both through `active_caps()`. A missing-neighbor cap cites each verified prior candidate. `unfair_baseline` may cap at 5 from the manuscript's own privileged or different-task baselines without a verified candidate, and it always cites the resolvable manuscript anchor `E-manuscript-baselines`.
- Only a confirmed candidate dated on or before the venue deadline can support `missing_closest_neighbor`. Concurrent work is discussion only. If every provider fails, times out, or no provider is available, `status=degraded` and no cap is emitted, so the score does not drop. If at least one provider succeeds and another fails, `status=partial` lists the failed providers and the report says the search may be incomplete. That partial search may emit `missing_closest_neighbor` only for a confirmed pre-deadline neighbour verified by a provider that succeeded and absent from the baselines. The same partial search still emits `unfair_baseline` when the manuscript anchor resolves. A failed provider never creates or strengthens a retrieval cap.
- Harness cap issues carry a bilingual `FirstReadNote` (what the paper said, a collapsed quote, why it matters) so `require_first_read_on_major` can pass. The baseline quote is the labeled experiment lines only, collapsed to one line and rendered as a blockquote. A section ends at the next real heading, so body prose does not leak into the labeled block.
- Named methods from the manuscript's related work, baselines, and references are extra name-only queries, so a cited closest method is retrieved and checked. Keyword queries stay generic tokens. Names are ordered by an explicit closest or most-related mention, then methods cited in the body, then experiment-table baselines, then related-work sentences nearest the paper's own method, then mention frequency. Hyphenated, camel-case, and digit-containing names such as `Foo-BAR`, `Abc3D`, and `XYZ-Net` are kept. The default cap is 15 (`named_method_limit`) and does not drop an explicit closest method or a reference cited in the body.
- Bibliography entries are resolved as metadata. Numeric markers (`[n]`, `n.`, `(n)`) and unnumbered author-year blocks are split even when a line wraps, starts with a year, or is only a year. The title is the quoted string, the sentence after the authors, or the sentence after the year. In-body cites include `[24]`, `[3, 24]`, ranges such as `[20–25]`, and author-year forms such as `Name et al. 2025` and `Name and Name 2025`. Entries cited in related work, the experiments, or the method section come first, then the citation nearest the method description. The default budget is 60 (`bibliography_lookup_limit`). An entry with no plausible title does not use a slot. arXiv titles use `ti:`. arXiv ids are batched with `id_list`. OpenAlex receives a sanitized title filter and, when the entry has a DOI, a DOI filter. A resolved cited reference is a candidate with `cited=true` and can be must-compare, which is the missing-neighbour case when the experiments do not compare it. Manuscript prose is not sent.
- Live retrieval and confirmation compose. After the search, the stage writes `confirmation_packet.json` (provisional must-compare candidates plus the manuscript baselines). Confirmation uses a `confirm_must_compare` hook, a `confirmation_adapter` only when that parameter is set, or an agent-written JSON file (`confirmation_path`, or a `confirmations` list on the findings drop). The `execute_review` adapter is not bound automatically. The retrieval cap cites only confirmed items. With no confirmation, the judgment is `awaiting_confirmation` and `require_related_work_confirmation` fails the export gate, instead of demoting those neighbours. The judge's confirmation or rejection reason is stored and reported verbatim. A generic sentence is used only when the judge gave no reason.
- The same paper returned by two providers is one candidate. Records merge on a shared arXiv, DOI, OpenAlex, or Semantic Scholar id, and on a title with punctuation, hyphens, and whitespace removed when the years differ by at most one.
- HTTP 429 is retried and does not abort the rest of that provider's queries. Semantic Scholar with `S2_API_KEY` uses a longer exponential backoff with jitter, honours `Retry-After`, and paces requests to about one per second. The key is not written into URLs, logs, or the cache. Without that key, a 429 that remains after 2 retries skips the provider inside an 8-second budget, and the search status lists it as failed. Successful provider metadata and HTTP 400 responses are cached in memory and on disk under the project `.autopaperreview/related_work_cache` directory, keyed by the provider, lookup kind, and query hash, for 7 days, so a resume after confirmation does not repeat the sweep. OpenAlex title filters drop commas, colons, quotes, and other characters that make the filter invalid. The candidate set is sorted so identical queries stay stable.
- The dimension table shows the assigned score and clause beside the after-ceiling band.
- `novelty` reads baselines against closest neighbours before it assigns tags. In one config, `novelty` and `rate` must depend on `related_work_search`. `rate` reads that comparison before it scores originality.
- Reports gain a bilingual Related Work section, and the stage writes `related_work.md` with suggested weakness and rebuttal sentences.
- Venue deadline sidecars: ICLR 2027 abstract 2026-09-18 and submission 2026-09-25; AAAI-27 abstract 2026-07-21 and submission 2026-07-28. See [related-work search](docs/related-work-search.md).
