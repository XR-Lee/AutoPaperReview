## Protocol

Model: Claude Opus 5.5, reasoning effort xhigh, through Cursor cloud-agent file handoff into a loopback chat server on `127.0.0.1`. No Anthropic API key and no other model API. Each arm has its own loopback. The server indexes the SHA-256 of the user message.

Locked `forecast-k1`, coefficient set `apr-fusion-v1`: `--cheap --holistic-mode forecast --holistic-samples 1 --related-work off`. The rank is `rank_score`. The venue bin is the 1–6 decision from the same call, mapped by `decision_bin`.

Pre-release was scored from the `9487ee6` tree. Main was scored from the `52aa237` tree. The paired intervals use `benchmarks/promotion/paired_bootstrap.py`. Every score uses coefficient set `apr-fusion-v1` and fusion variant `forecast-k1`.

Calls: 48 first answers, one per paper per arm. Nine of those answers added fields that `ForecastJudgment` rejects. Each of those nine had the one allowed schema retry. The retry kept the same review ratings, the same `predicted_mean`, and the same decision rating, and dropped the extra fields. After that retry, `ForecastJudgment` accepted every answer. Parse-failure count after the allowed retry is 0 on each arm. Pipeline-failure count is 0 on each arm. The loopback returned status 200 for 24 messages on each arm and no other status. It records `prompt_tokens: 0`. At the published Opus figure of $0.66 per call, 48 first calls plus 9 retries are about $37.62, under the $100 cap.

The pre-release task text is 7229 characters, SHA-256 `3611121d0cee15e7f503e2dd90557bbbcaf4b3ea48f487b5cd7ba127a53889e4`. The main task text is 6780 characters, SHA-256 `4374696de5c606470815b72c53ac5382afbeab79501f651c86608241fe1800b7`. These are the same task texts as the 192-paper Grok run. User messages match on 0 of 24 papers, because that task text differs. The 240000-character cap cuts 1 paper on each arm, and the cut flag matches on that paper. 23 papers are uncut on each arm.

Sixteen manuscripts came from an exact arXiv title match. Eight had no exact arXiv match and were read from OpenReview before any model call.

The decision intervals are the paired stratified bootstrap: one draw applied to both arms, strata restored with replacement in sorted stratum order, 4000 resamples, seed `20261029`, linear percentiles 0.025 and 0.975. All 4000 resamples were defined on every primary comparison below. A higher-is-better metric is worse beyond the interval when the whole interval is below zero. MAE is worse beyond the interval when the whole interval is above zero. An interval that contains zero is unchanged for this rule. An endpoint of zero is not entirely on the worse side.

## What the failure is

The failure is the venue bin, not the rank score. Pre-release's 1–6 decisions sit lower (signed error -1.0326 against -0.9076) and line up less well with the official bins. The whole intervals for bin Spearman, bin Kendall, bin MAE, and reviewer bin agreement are on the worse side. Accept/reject separation on the bin is almost the same, and the rank metrics are unchanged inside their intervals.

Both arms still order the four tiers by mean `rank_score`. The clear-accept tier is the one both arms under-score by about two points. That compression is larger on pre-release in the tier table, and it shows up in the bin MAE.

No prompt, coefficient, packet cap, or scoring path was edited after these answers were read. The nine schema retries changed no scored number. This holdout is not a fitting set.

## Verdict

**FAIL.** Gate 1 does not hold: four venue-bin metrics are worse beyond their paired intervals. Gate 2 holds: parse failures after the one allowed retry are 0 and pipeline failures are 0 on pre-release, equal to main. Gate 3 holds on this pre-release commit, as recorded in the 192-paper report. A promotion requires all three gates.
