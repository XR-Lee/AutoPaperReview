## Protocol

Model: grok-4.7, reasoning effort xhigh, through Cursor cloud-agent file handoff into a loopback chat server on `127.0.0.1`. No xAI API key and no other model API. Each arm has its own loopback. The server indexes the SHA-256 of the user message.

Locked `forecast-k1`, coefficient set `apr-fusion-v1`: `--cheap --holistic-mode forecast --holistic-samples 1 --related-work off`. The rank is `rank_score`. The venue bin is the 1–6 decision from the same call, mapped by `decision_bin`.

Pre-release was scored from the `9487ee6` tree. Main was scored from the `52aa237` tree. The paired intervals use `benchmarks/promotion/paired_bootstrap.py`. `ForecastJudgment` accepted every fresh answer. Parse-failure count is 0 on each arm. Pipeline-failure count is 0 on each arm.

Calls: 312 fresh answer files (132 on pre-release, 180 on main). Reused without a new call: 60 on pre-release and 12 on main. The 60 are the previous 48 dev papers, scored earlier on the accept-anchor prompt at this pre-release line, plus the 12 papers that moved into the dev set from the previous holdout. Main reuses only those 12, which were produced at `52aa237`. Main does not reuse the 48 judgments produced at `3865669`. One dev-cache PDF was a byte-for-byte copy of a different paper. It was replaced from OpenReview before that paper was scored. Both arms of that paper used the corrected file. There was no second call for a parse failure. The loopback records `prompt_tokens: 0`. At the published Grok figure of $0.11 per paper, 312 calls are about $34.32.

The pre-release task text is 7229 characters, SHA-256 `3611121d0cee15e7f503e2dd90557bbbcaf4b3ea48f487b5cd7ba127a53889e4`. The main task text is 6780 characters, SHA-256 `4374696de5c606470815b72c53ac5382afbeab79501f651c86608241fe1800b7`. User messages match on 0 of 192 papers, because that task text differs. The 240000-character cap cuts 9 papers on each arm, and the cut flag matches on every paper. 183 papers are uncut on each arm.

`ForecastJudgment` JSON Schema matches across the two refs (SHA-256 prefix `41762b67f10aec4e`). `fusion.py`, `public_calibration.py`, `rank_metrics.py`, and `rating.py` match. `model_exec.py` differs only in `forecast_task_text()`.

The decision intervals are the paired stratified bootstrap: one draw applied to both arms, strata restored with replacement in sorted stratum order, 4000 resamples, seed `20261029`, linear percentiles 0.025 and 0.975. All 4000 resamples were defined on every primary comparison below. A higher-is-better metric is worse beyond the interval when the whole interval is below zero. MAE is worse beyond the interval when the whole interval is above zero. An interval that contains zero is unchanged for this rule.

Stored scores for both arms are in the agent-store baseline cache, `fixed-eval/baseline-cache/pre-9487ee6-grok` and `fixed-eval/baseline-cache/main-52aa237-grok`. Each directory has `metadata.json` and `papers/<id>/our_score.json`. `load_baseline_cache` returns those scores only when the commit, model id, effort, and manifest digest match. `scripts/rank_eval.py --baseline-cache` fills a local cache that has the human file and no score yet.
